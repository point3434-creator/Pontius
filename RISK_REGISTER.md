# Risk Register

| ID | Risk | Warning sign | Mitigation / stop condition |
|---|---|---|---|
| R1 | Metrics fail to predict full-game strength | Exact improvements reverse in every realistic league | Freeze hidden suites; build independent responders; stop architecture work if measurement is untrustworthy |
| R2 | Incorrect rules or regret math | Failure to reproduce small known games | Slow reference, property tests, differential implementations; correctness blocks optimization |
| R3 | Multiplayer CFR gives misleading apparent convergence | Self-play improves while unilateral deviations grow | Report exact NashConv in tractable games; compare current, average, and snapshot policies |
| R4 | Neural leaves have low MSE but damage root play | Root harm worsens on insertion | Root-aware gates; retain blueprint continuation; stop scaling the model until targets are fixed |
| R5 | Adaptive search neglects rare adversarial branches | Restricted responder steers into cold lines | Minimum coverage and worst-case vulnerability budgets |
| R6 | Learned scheduler overfits its oracle | Beats heuristic only on training games | Hidden games, conservative uncertainty bonus, permanent heuristic fallback |
| R7 | Premature kernel optimization | Fast synthetic benchmark with no end-to-end gain | Optimize only captured representative traces |
| R8 | Host/GPU memory exhaustion | Peak use leaves no transient headroom | Target <=48 GB host and <=13 GB GPU steady state; report bytes per structure and enforce quotas |
| R9 | Single-developer scope overload | Multiple incomplete subsystems | One active checkpoint, three immediate tasks, explicit kill criteria |
| R10 | Agreement bias hides flaws | Decisions contain no opposing evidence | Mandatory dissent format and falsifying experiment for consequential choices |
| R11 | Inaccessible Pluribus prevents headline comparison | Internal league becomes sole evidence | Maintain a Pluribus-style control, independent responders, and precise limited claims |
| R12 | Shallow resolving damages a strong blueprint even with exact leaves | Exact-control NashConv exceeds blueprint NashConv | Require paired exact-control gate, variant-neutral anchoring, and an explicit blueprint/no-op fallback before neural scaling |
| R13 | Anchor and no-op thresholds overfit independent errors in a tiny game | Selected coefficient reverses under correlated errors or a new player count | Freeze selection rules before held-out games; require reach-weighted structured-error and multiplayer gates |
| R14 | Joint-reach weighting hides rare but strategically pivotal value errors | Equal on-policy root error causes greater harm when localized in cold branches | Track per-player counterfactual error and local uncertainty; enforce minimum coverage; test adversarial branch targeting |
| R15 | Low leaf risk is mistaken for positive value of search | Near-exact leaves still produce a worse candidate in some depths or blueprint regimes | Require an independent resolver-benefit lower bound; risk may veto but never authorize search by itself |
| R16 | Local resolver improvement fails when composed with unsolved continuation play | Local NashConv falls while full-game NashConv rises, even with exact continuation values | Evaluate a complete continual resolver; track policy displacement; require full-game or safe-frontier evidence before freezing a benefit gate |
| R17 | A common Bayesian posterior is mistaken for a safe replacement frontier | Posterior-correct continual resolves improve locally but open profitable earlier or off-path deviations | Reproduce two-player opponent-CF-value gadget guarantees; treat multiplayer constraints as measured relaxations, not transferred theorems |
| R18 | A theorem-correct gadget is mistaken for an efficient resolver | Finite CFR residual permits harm, or exact certification rejects nearly every candidate and costs more than the gain | Measure one-sided residual and certificate latency; keep strict no-op; compare against an exact constrained/max-margin oracle before optimizing kernels |
| R19 | Constraint generation hides exponential work inside pricing or separation | Small LPs look fast while responder traversals or active scenarios dominate latency | Price with dynamic best response; report active rows/columns and phase timing; require held-out quality/ms before kernel work |
| R20 | Similar-looking ranges authorize an invalid strategy-cache hit | A rare blocker hand has a different conditional range or best response despite high root overlap | Deploy cached strategies only on exact joint-range provenance; treat structural/approximate matches as topology reuse or warm starts; recertify under the current range |
| R21 | Two-player safety language is transferred to multiplayer constraints | Unilateral metrics look acceptable while a coalition or correlated field response causes large loss | Call multiplayer output constraint-screened, not safe; report unilateral NashConv plus explicit coalition/team best-response threat models before deployment claims |
| R22 | A scheduler feature is accidentally equivalent to its exact target in a shallow game | Regret has near-perfect rank correlation only where every player acts once | Prove and test small-game identities; require transfer to sequential multi-action trees before fitting or freezing a scheduler |
| R23 | Scheduler evidence optimizes free features or total headroom instead of quality per millisecond | High opportunity correlation collapses after dividing by future work, or an allocator uses a feature before paying its probe cost | Make gain per deterministic work the primary target, replicate with measured milliseconds, enforce a minimum paid checkpoint in allocation controls, and reject rules that cannot beat the matched fixed checkpoint |
| R24 | Development cross-validation is mistaken for unseen transfer after the feature family was designed on the same development trace | Internal folds pass but a fixed rule reverses on new boards | Label internal folds as development only; commit one selected rule before constructing validation; reject without retuning if any frozen validation gate fails |
| R25 | A degenerate exact teacher cycles or violates floating-point simplex tolerances | Pivot count explodes or primal/dual verification aborts on a new normal form | Use a bounded packing fast path plus two-phase fallback; record backend and pivots; require original-matrix duality and behavioral NashConv verification for every teacher |
| R26 | A small exact heads-up river scheduling win is mistaken for a six-player or wider-tree result | The frozen rule loses its rate edge after adding bet sizes, deeper action sequences, belief shifts, inference, or concurrent runtime contention | Keep the rule as a narrow control; require held-out richer-action and multiplayer gates with all feature, recertification, queueing, and inference costs before any production or neural-scheduler claim |
| R27 | Exact-source cache reuse looks nearly free because source construction is treated as sunk | Warm or recertified reuse wins only when a 100+ ms exact teacher is excluded, then reverses for finite policies or low reuse counts | Test finite source checkpoints, record source residual and construction cost, report break-even reuse counts, and require an exact incremental-recertification control before cache promotion |
