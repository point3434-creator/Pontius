## Outcome and acceptance

Deliver a CPU-only outer evaluation loop that compares baseline-rules-v1 against
blueprint-v1 through the unchanged public session CLI. Each trial is one hand with
fresh 200-chip stacks. The same full table bytes serve both strategies. Every planned
deal/lineup covers all six controlled seats; starting button is configurable. This
is a reusable correctness asset whose actual evaluation populations remain unadmitted.

1. Strict canonical requests determine the complete ordered trial matrix before play.
2. Existing seeded-deal recipe and four opponent scripts are reused unchanged.
3. Every matched pair has identical cards, board, button, stacks and opponents; only
   strategy/protocol/run identity differs. Six-seat rotation does not rotate away
   relative position. Stack resets prevent policy-dependent dropout of later deals.
4. Public session admission, legal engine, provider, fallback and action clock remain
   authoritative. The parent never selects poker actions or delivers full deals to policy.
5. A fresh create-only output root, per-trial intent and retained raw captures make
   failures observable. No resume, retry, replacement arm, dropped row or silent success.
6. Reports separate completed-pair chip deltas, applied action counts, provider fallback,
   legacy blueprint choices, observed timing flags, action/hand/session failure scopes
   and incomplete observations.
7. Windows descendants are contained before executable work, captures have byte caps,
   and one shared monotonic deadline governs trial admission and publication commit
   verification. Postcommit guard release/visibility may occur later; no hard wall claim.
8. Finite independent correctness controls and both supported interpreters establish
   the machinery; no observed profitability is a source-acceptance gate.
