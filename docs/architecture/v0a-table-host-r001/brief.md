# One-hand reactive table host: brief r001

Status: proposed design; no source opening or operating authority.
Task: v0a-table-host-design/r001. Base: 1329c2c201bbf2f396946f2ebf460ee944ae4ece.
Tier C: private-card isolation, semantic action application, settlement and
child-process ownership. Finalizer: Codex. User selected completion before strength.

## Outcome and scope

Add a CPU-only local table host for one complete six-seat hand. It owns the
explicit deal, applies real Pontius pipe actions, selects simple opponent actions
from the resulting public state and independently checks the terminal settlement
against its dealer-side result. No prewritten future opponent action sequence or
expected payout is accepted as input. The first source increment is the table
loop shared by later terminal and automated sessions, not either presentation.

The host is a new tools/v0a_table_host.py, preserving every existing runtime/tool
byte. No src/pontius addition: the accepted event adapter's package inventory is
closed. The host may use the accepted public game/model/codec helpers. It never
imports the event adapter or accesses a private Pontius runtime or ledger member.
Its child executes the unchanged event adapter in a contained Windows process.

## Acceptance criteria

1. Real child-process actions alter the authoritative host table exactly once;
   opponents choose only after that exchange completes. The same input deal
   with a different legal bot policy can change subsequent opponent behavior.
2. Run finite independent fold, showdown and unequal-stack/all-in side-pot cases
   through the public CLI. Verify actual actions, payouts, final stacks and chip
   conservation against explicit expectations, not results generated by the host.
3. Opponent selectors receive only their own cards, public state and legal
   choices. Bot input contains only its own cards and public events, with ranks
   supplied only after all betting ends. No full deal or unrevealed card leaks.
4. Compare action identity and legality before application; require matching
   event diagnostics, terminal reports, EOF and exit zero for host success.
   Duplicates, unsolicited/missing actions, state mismatches, malformed frames,
   wrong identities, false success, partial output and late failures stop the hand.
5. Preserve an applied action when a later result fails. Never replay, withdraw
   or complete an ambiguous action through a second application. A failed hand
   cannot become a settled success merely because chips can be calculated.
6. The child is assigned to a kill-on-close Windows job before the fixed bootstrap
   releases it into the bot tool. Bound pipe capture and waits; verify native
   child/descendant termination and retain primary failure before cleanup faults.
7. Preserve raw source/import admission, original bot wire/timing contracts,
   old inventory rows, zero capability grants and all old acceptance predicates.
8. Pass focused and named regression checks in fresh D-local snapshots on actual
   CPython 3.11.15 first, then 3.14.6. No GPU or optional dependency is required.

## Ground truth, dependency and limits

Ground truth is the accepted exact game/event contracts plus the three manually
specified deals and arithmetic in design.md. Host and bot share game kernels;
agreement alone is not independent game-rule proof. Tests must also use those
fixed independent expectations and consumer falsifiers at real boundaries.

Only the local terminal/session application waits on this host. Training, league
evaluation, neural inference, resolver work, H32, Gate 13, analyzer repair and
compiled work are separate and remain parked. Source correctness testing does
not need an operational owner under ADR-0489. Arbitrary-deal/human sessions still
need their later operating-entry decision; correctness IDs do not authorize them.

No GUI, human input, network play, random deal generation, multi-hand session,
training data claim, policy improvement, speed/strength result or new trace format.

## Budget and stop rule

At most 1200 new production LF lines in the one tool, 1600 combined LF lines in
two new suites, four new fixture files totaling at most 16384 bytes, and 200
manually added/removed registration lines. Generated inventory outputs are
counted separately. Tests may exceed production because they must exercise the
real pipe/job and falsify card, action and settlement boundaries independently.

One initial design candidate plus at most one bounded correction; two independent
Tier C reviews per substantive candidate. The future implementation has the same
two-candidate budget. A qualified mechanical correction follows ADR-0492 exactly.
Stop before expanding files, budgets, private access or authority. A third round
requires a new controller ruling, not a silent continuation.
