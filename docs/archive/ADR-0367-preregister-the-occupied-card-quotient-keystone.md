## Validity precondition

For one directional pass, let `S` be the seats represented by the source half
and `Q` the seats represented by the query half. The quotient is valid only
when every seat in `S` is fully summed and every open private-hand axis belongs
to `Q`. For a source labeled assignment `a`, let `occ(a)` be its union of hole
cards and let `x_a` contain all seat-specific unary, mixture-component, and
left/right tensor-train factors for that assignment. Then

```text
C[M] = sum_{a: occ(a) = M} x_a
```

is lossless because the cross-half card-conflict predicate depends on `a` only
through `M`. Seat identity is not discarded: it has already contributed inside
the sum defining `C[M]`. What is discarded is only the multiplicity of labeled
deals with the same occupied-card union.

The alternating one-seat architecture must therefore place each requested
target seat in the query/right half for its own pass. The left/source three
seats are summed spectators. A source-open request must reject before any
aggregation. This is a semantic precondition, not a favorable seat-order
assumption. A future runtime may batch targets only when this condition still
holds for every batched output.

Known singleton cards, such as the controlled hand, may be projected out of a
query mask only after proving that they are absent from every source axis. The
source and query fixed masks must be disjoint. Projection may not hide a live
card conflict.

## Exact operator

For a query occupancy mask `L`, the desired source sum is

```text
y[L] = sum_{M: M & L = 0} C[M].
```

Define the containment marginal

```text
Z[T] = sum_{M: M superset T} C[M].
```

Then finite inclusion-exclusion gives

```text
y[L] = sum_{T subset L} (-1)^|T| Z[T].
```

Subsets larger than a source occupancy have zero marginal and need not be
stored or visited. The reverse/open operator is not an informal symmetric
analogy: it is the exact transpose of the same disjointness matrix. The
keystone must check both directions and the exact dot-product identity. A
runtime successor may implement containment sums by a zeta/Mobius transform,
combination-ranked arrays, generated subset visits, or another exact layout,
but it must reproduce this reference operator.

## Frozen arithmetic

With 45 cards available, three labeled opponent pairs occupy six cards:

```text
C(45, 6) = 8,145,060 occupancy masks
6! / (2!)^3 = 90 labeled pairings per mask
8,145,060 * 90 = 733,055,400 labeled assignments.
```

Two labeled opponent pairs occupy four cards:

```text
C(45, 4) = 148,995 occupancy masks
4! / (2!)^2 = 6 labeled pairings per mask
148,995 * 6 = 893,970 labeled assignments.
```

For the six-card source/four-card query pass, each source mask contributes to
`sum(k=0..4, C(6,k)) = 57` marginals and each query uses `2^4 = 16` signed
terms. In the transposed four-card source/six-card query pass, each source mask
contributes 16 marginals and each query uses
`sum(k=0..4, C(6,k)) = 57` terms. Both directions require only containment keys
through cardinality four:

```text
sum(k=0..4, C(45,k)) = 164,221.
```

These are exact combinatorial counts, not an allocation, bandwidth, GPU,
latency, or complete-contraction estimate. Feature width, automata, tensor
trains, query records, scratch, grouping work, refresh work, and result storage
remain unpriced.

## Source-only keystone

The implementation must be a pure CPU reference over bounded card universes.
Exact rational arithmetic is the authority; Float64 comparisons to the
current stack use the current numerical allowances and are differential only.
It must cover all of the following before any full-width bound is sealed:

1. exact forward output versus literal labeled-record compatibility;
2. exact transpose output and exact dot-product/adjoint identity;
3. scalar and one-open-axis agreement with dense enumeration and the current
   FactorTT/bidirectional open-mode implementation;
4. multiple mixture/features, signed values, zero and sparse weights, and
   adversarial cross-half card conflicts;
5. fixed-card projection whose projected cards are proven absent from source;
6. source-open, overlapping-seat, and unsafe-fixed-card requests rejected;
7. a three-source-seat relabeling control in which simultaneously permuting
   seats, hands, and weights produces bit-identical canonical quotient
   coefficients and outputs; and
8. a one-source-seat unary-weight change whose topology-stable coefficient
   refresh is canonically identical to a cold rebuild.

The safe reference refresh may recompute every coefficient while reusing the
immutable occupancy grouping. A later incremental or device implementation is
an optimization only and must remain behind cold-rebuild identity; this ADR
does not claim incremental-refresh speed.

The reference may enumerate labeled assignments only inside bounded controls
and may never be connected to a full-width target. Its work ledger must report
source records, unique source occupancies, source marginal updates, query
records, and signed query terms separately. It may not rename labeled-record
work as occupancy work.

## Kill criteria

Kill this mechanism before a full-width bound if any exact dense, transpose,
dot-product, permutation, refresh, fixed-card, or invalid-scope control fails;
if a current FactorTT/open-mode differential exceeds its inherited numerical
allowance; if reverse/open semantics require an open source seat; or if exact
card conflict cannot be represented without restoring persistent labeled-half
records.

After the algebra passes, the next separate source seal must derive literal
full-width persistent and scratch bytes plus cold and warm operation counts for
all feature widths and both directions. It must include query-side labeled
records, aggregation, automata, tensor trains, result vectors, workspaces, and
CPU/GPU placement. Failure of that bound closes the layout; passage opens only
a later GPU keystone, not a full solver.

## Claims boundary

This ADR preregisters an exact representation hypothesis. The 90-fold and
six-fold quotient multiplicities do not establish a 90-fold runtime or memory
speedup. The 164,221-key count is not a complete memory bound. No full-width
allocation, warm contraction, CFR iteration, solve, 15-second action, decision
quality, support-truncation certificate, or poker-strength result exists.
Certified support truncation remains a separate later hypothesis and cannot be
selected from ADR-0366 or this algebra gate.
