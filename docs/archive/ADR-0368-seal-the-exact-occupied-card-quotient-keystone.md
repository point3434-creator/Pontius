## Exact reference contract

`OccupiedCardQuotientTopology.compile` binds source, query, and open seat sets;
original record masks; optional fixed masks; projected variable masks;
canonical unique source occupancies; labeled-record group IDs; and exact group
multiplicities. It requires disjoint source/query seat sets, makes the
ADR-0367 source-closed/query-open precondition executable, and proves that any
projected fixed card is absent from the opposite variable half.

`aggregate_exact` converts every supplied binary float, integer, or rational
to its exact rational value and sums complete record features by canonical
occupancy mask. `apply_coefficients_exact` constructs containment marginals
only through the opposing occupancy width and evaluates every query by signed
inclusion-exclusion. `apply_adjoint_exact` aggregates query rows by occupancy,
applies the transposed disjointness transform, and expands the result back to
every labeled source record. The work type keeps labeled source records,
unique source occupancies, marginal updates, labeled query records, signed
query terms, and feature width separate.

`refresh_one_source_seat_exact` verifies that the named seat is closed and
that the prior coefficient masks and width match. It then recomputes all new
coefficients against the immutable grouping. This establishes refresh
semantics only. It is not a delta algorithm or a refresh-latency result.

## Limits and next boundary

The reference still stores and walks bounded labeled records before
aggregation. It supplies no combination-ranking layout, full-width coefficient
builder, device array, kernel, refresh optimization, cache policy, or resource
admission. Its 90-fold state quotient is exact, but no 90-fold memory or speed
claim follows because query records, feature widths, subset tables, scratch,
automata, tensor trains, aggregation work, and results remain unpriced.

The next checkpoint is source-only arithmetic, not allocation: derive exact
persistent and peak-scratch bytes and logical cold/warm work for both
directions on the frozen 45-card fixture. It must distinguish the six-card
source/four-card query and its transpose, retain labeled query axes needed for
open-seat grouping, parameterize every component/rank/automaton width, state
every excluded class, and fail against the same 48 GB host/12 GB device caps
and reserves before any runtime source exists.

## Claims boundary

ADR-0368 establishes only that occupied-card union is a lossless quotient for
fully summed source seats and that the exact containment/inclusion-exclusion
operator plus its transpose reproduce bounded literal, dense, and current
FactorTT semantics. It does not establish scalable construction, full-width
capacity, GPU feasibility, warm latency, a CFR iteration, solve, complete
15-second action, decision quality, support truncation, or poker strength.
