## Exact recurrence

For source cardinality `s`, let `C(S)` be the feature vector for an occupied
source set `S`, and define

```text
Z_s(S) = C(S)
Z_k(T) = [sum over x not in T of Z_(k+1)(T union {x})] / (s - k)
```

for `k = s-1, ..., 0`. Every `s`-set containing `T` appears exactly `s-k`
times in the numerator, so `Z_k(T)` is exactly the containment marginal
`sum_{S superset T} C(S)`. A query mask `Q` is evaluated by

```text
sum over T subset Q of (-1)^|T| Z_|T|(T).
```

The forward has `s=6`, four-card query masks, and 16 signed terms. The adjoint
first sums six labeled query records per four-card occupancy, applies the same
recurrence with `s=4`, evaluates six-card source masks with 57 signed terms,
and only then streams the 90 labeled source pairings when record-level output
is requested. The adjoint is the same matrix transposed; it is not a fixed
reverse split and never opens a source seat.

Colexicographic combinadic rank/unrank and cardinality offsets are the only
set indexing authority. No hash table, source-mask table, sparse incidence
matrix, or atomic floating-point accumulation is permitted. One output row
and feature is owned by one thread; accumulation order is deterministic.

For 45 cards and `s=6`, the recurrence owns 9,531,040 rows across cardinalities
zero through six and 55,619,730 vector-edge additions. At fixture width 176 it
therefore performs exactly 9,789,072,480 scalar edge additions, rather than
ADR-0370's 81,711,241,920 direct subset-update additions. This is an exact
logical-work identity only. It is not a measured speedup and does not erase
the twice-per-batch source-pairing work.

## Direct automaton and affine fold

The source coefficient kernel consumes the first three transitions of the
direct structured showdown automaton. For each canonical six-card occupancy,
it visits all 90 labeled three-pair deals and applies every source-seat unary
and mode factor before aggregation. Its columns are every state after the
third source seat plus one reach column for each mixture component and term.
It may never aggregate first and apply seat-specific factors later.

The query side applies the hero singleton and both labeled query hands through
the remaining direct transitions. Numerator is `winner + sunk * reach`; sunk
must not receive a duplicate source feature. Mixture, query unaries, and query
mode factors are applied only on the query side. A source-seat unary change is
a topology-stable **full source refresh**: rebuild coefficients and every
recurrence level. Only query-side changes may reuse the source marginals.

## Frozen bounded population

The natural population is all `C(10,6)=210` six-card source occupancies, all
18,900 labeled source pairings, all `C(10,4)=210` query occupancies, and all
1,260 labeled query records. One deterministic two-component, non-dyadic
Float64 fixture supplies:

- pair-to-hand indexing and implicit-rank boundary cases;
- source- and query-seat-specific unary weights, including exact zeros;
- direct automaton strength ties and multiple winner classes;
- distinct component mixtures and sunk values;
- a one-source-seat unary perturbation and a query-only perturbation.

The source fixture and its mutations are defined in source, not discovered
from device outcomes. Exact expectations are rebuilt with `Fraction.from_float`
through ADR-0368's operator, plus independent dense and current-stack checks
where their bounded interfaces apply. Fraction is faithful to the frozen
Float64 inputs; it is not evidence about an intended pre-rounded rational.

Separate engineered controls include a signed three-feature forward/adjoint
matrix, a source-seat relabeling, colex boundary masks, a maximum-conflict
query, a wrong recurrence divisor, a reversed inclusion-exclusion sign, a
dropped source factor, a duplicate sunk column, and an adjoint seam that skips
labeled-query aggregation. Mutations must fail the relevant differential.

## Frozen numerical and repeatability gates

Discrete geometry, ranks, masks, group counts, work counts, refresh class, and
allocation bytes are exact equality gates. Natural device output must satisfy
all of these separately named Float64 maxima:

```text
maximum source-coefficient absolute error       2e-12
maximum forward-row absolute error              2e-10
maximum adjoint-row absolute error              2e-10
maximum affine-fold absolute error              2e-10
maximum forward/adjoint dot-product error       2e-10
maximum scale-normalized relative error         2e-11
```

The relative denominator is `max(1, abs(exact_reference))`. These constants
are independent semantic fields; no one field may be reused as another gate,
as a tie rule, or as a clock allowance. Two same-process warm executions must
be byte-identical for numeric outputs and exact-identical for work. If the
platform violates that deterministic contract, the keystone rejects rather
than widening a tolerance after observation.

## Preallocation and work gates

Every device run performs pure integer preallocation arithmetic before CuPy
import, context creation, kernel compilation, or numeric allocation. It then
repeats admission against live free bytes before the first numeric device
array. An engineered oversize request must reject while a trap proves that
CuPy was never imported or called.

The equivalent recurrence workspace uses feature batches no wider than 128.
For the 45-card arithmetic fixture, all cardinality levels occupy
9,759,784,960 bytes at batch width 128. A 65,536-record query chunk adds
67,108,864 bytes. Existing fixture persistent bytes remain separately charged.
These arithmetic values may be asserted without allocating them. The safe
2,971-column envelope needs 24 batches, not a wider resident table. A later
literal gate must independently price every implementation array and require
both the fixed 12,000,000,000-byte numeric cap plus 2,000,000,000-byte reserve
and live-free-memory reserve; this keystone cannot satisfy that later gate.

Device work records separately expose source pairing visits, coefficient
accumulations/zeroing, recurrence vector edges and scalar additions, signed
query terms/additions, automaton folds, query aggregation, adjoint recurrence,
signed source terms, and optional label writes. A source refresh must report
the same source/recurrence work as cold. Query-only refresh must report zero
source/recurrence work. Feature batching may multiply pairing visits but may
not alter the operator.

CUDA events separately measure source coefficient construction, recurrence,
signed query evaluation, affine folding, adjoint aggregation/recurrence/query,
and total synchronized device wall. A host monotonic wall includes validation,
transfer, compilation, and synchronization. The bounded natural control has a
30-second laboratory guard only to catch a hang; passage is not a latency
claim. No advertised FLOPS, reduced ratio, or arithmetic projection may enter
a gate for the 45-card target.

## Kill criteria

Reject the keystone if any exact/dense/current-stack differential fails; if
the recurrence mutation survives; if rank collisions occur; if source-seat
permutation or cold/refresh identity fails; if forward/adjoint dot products
disagree; if any frozen numerical envelope or warm byte identity fails; if an
atomic Float64 accumulation or explicit incidence/source-mask table appears;
if the allocation trap observes CuPy before rejection; if work depends on
Cartesian labeled-source materialization rather than 90 visits per occupancy;
if a target/open seat appears on the source half; or if the bounded entry point
can accept the 45-card target.

Failure does not authorize truncation, tolerance repair, a larger cap, a
second population, or an alternate action. Any recurrence or workspace change
requires a new prospective source boundary. Passage authorizes only a
separately preregistered staged-width/live-admission experiment.
