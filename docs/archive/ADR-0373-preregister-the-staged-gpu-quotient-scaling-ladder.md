## Frozen repetitions and measurements

For each admitted stage, the owner performs in this order:

1. pure fixed-cap arithmetic, live free-memory admission, topology construction,
   device transfer, and one cold forward;
2. five identical warm full forwards, each rebuilding source coefficients and
   every recurrence level;
3. three full source-refresh forwards under the frozen changed source unary;
4. five query-only evaluations reusing unchanged source marginals;
5. one cold plus three warm unique-occupancy adjoints at width 128, with labeled
   query aggregation and no 90-fold record expansion;
6. numerical, work, repeatability, direct-sample, affine, dot-product, memory,
   and provenance gates before the durable stage record.

CUDA events report each kernel phase. Host monotonic walls separately report
topology, allocation/transfer, cold, warm campaign, source-refresh campaign,
query-only campaign, adjoint campaign, validation, stage total, and cumulative
campaign. Each repeated phase reports all raw observations, median, maximum,
and count; no selected fastest observation is permitted.

Stage host wall is capped at 120,000 ms and the shared campaign wall at
600,000 ms. A wall crossing retains a typed completed rejection and stops.
These laboratory hang/capacity guards are not the 14-second compute budget and
may not be compared with a complete decision.

## Frozen numerical controls

Each stage independently requires:

- 16 prospectively derived source occupancy ranks to match a host direct
  90-pair coefficient builder at maximum absolute error `2e-12`;
- eight prospectively derived query occupancy ranks and features
  `0, 1, 2, 31, 63, 95, 126, 127` to match a separate device literal
  disjoint-source scan at maximum absolute error `2e-8` and normalized
  relative error `2e-11`;
- eight query affine rows to match a host direct automaton fold from the
  independently returned compatible features at maximum absolute error
  `2e-10`;
- the width-128 forward/unique-adjoint dot product to agree within absolute
  `2e-8` and normalized relative `1e-10`;
- all five warm forward outputs, all three source-refresh outputs, all five
  query-only outputs, and all three warm adjoints to be pairwise byte-identical
  within their semantic class;
- exact geometry, rank, work, refresh-class, allocation-byte, stage-order, and
  repetition counters.

Sample ranks derive from SHA-256 of the literal tuple
`pontius|adr-0373|stage=<n>|lane=<source-or-query>|index=<i>` modulo the relevant
occupancy count, with zero and the final rank inserted and duplicates resolved
by increasing rank modulo the axis. No observed value may influence a sample.

The direct selected-query kernel owns one thread per selected query-feature
and scans implicit colex source rows. It may not call the recurrence. The
adjoint aggregates six labels, uses the four-card recurrence, and emits only

## Terminal and stop semantics

Only these terminal classes are valid:

- `completed_pass`: all six ordered stages complete and every gate passes;
- `completed_stage_rejection`: a numerical, work, repeatability, wall, fixed-
  cap, or live-admission gate rejects at the named stage and no later stage is
  called;
- `infrastructure_failure`: source/provenance/device/journal/compilation or an
  unexpected exception prevents a scientific interpretation.

There is no partial pass, skipped stage, retry, population repair, tolerance
change, allocation-cap enlargement, selected repetition, or continuation after
rejection. A pass does not authorize 45 cards. A rejection does not authorize
truncation. Either scientific terminal only informs a separately preregistered
literal-or-representation successor.
