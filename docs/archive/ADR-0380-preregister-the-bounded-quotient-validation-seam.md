## Decision

no arguments and executes only complete 10- and 22-card fixture populations in
that order. Any allocation helper called with another width, including 45,
must reject before importing CuPy. It may reuse the hash-sealed source,

journal, compile a target fixture, or allocate a target-shaped array.

bytes, so the frozen 67,108,864-byte window produces two nonempty chunks. The

## Frozen population and execution

For each width, construct the complete immutable ADR-0373 fixture at rank 127
and feature width 128. The ordered device lifecycle is:

1. pure bounded allocation arithmetic and reject-before-import control;
2. clear default and pinned pools, validate the ADR-0373 device/software
   identity, sample physical free/total bytes, and admit only the bounded model;
3. allocate the forward state and exactly one active unary device buffer;
4. run one cold forward, copy complete source/compatible/numerator/reach outputs
   into host references through the fixed staging window, rerun, and compare
   every literal byte;
5. overwrite the active unary with the frozen source-refresh unary, run once,
   replace the same host references, rerun, and compare complete bytes;
6. overwrite the active unary with the query-only unary, reuse source state,
   run once, update only the scalar host reference, rerun, and compare source,
   compatible, numerator, and reach bytes;
7. run the independent selected-query direct scan and exact source/affine
   samples without calling the recurrence as their oracle;
8. allocate the deterministic query covector, copy it to the host window in
   chunks, and compute the forward dot against the complete host compatible
   reference without a full device product;
9. record and release recurrence, compatible, numerator/reach, query topology,
   forward automaton, and active-unary device ownership; free cached dead
   blocks while preserving the query covector;
10. allocate one aggregated query array, one four-card recurrence, and one
    unique source adjoint; compute the transpose dot against the retained host
    source reference, then overwrite that same large host buffer with the
    unique adjoint and prove one repeat byte-identical; and
11. release every owned array, clear both pools, synchronize, and require zero
    used/total default-pool bytes, zero pinned free blocks, unchanged device
    total, and recovery of pre-run physical free memory within the frozen
    16-MiB infrastructure allowance.

Only one complete large host reference buffer is live. It contains source
coefficients until the transpose dot closes, then unique-adjoint bytes. Hashes
are reporting-only; every repeatability gate compares each literal byte.

## Streamed dot contract

The device never evaluates `compatible * query_covectors`, `source * unique`,
or another full elementwise product. Device operands are copied in increasing
contiguous chunks into the same host staging window. Each chunk is evaluated
with Float64 `dot`; its scalar partials are combined with `math.fsum` in chunk
order. Forward and transpose use the same partition and accumulator contract.
The pure exact oracle proves operand and partition identity; the device gate
freezes numerical acceptance at absolute `2e-8` and normalized relative
`1e-10`, unchanged from ADR-0373.

The mechanism reports both scalar dots, absolute/relative difference, chunk
counts, every `(start, stop)` span, and SHA-256 of each complete host operand.
No per-chunk time is converted into an iteration, solve, or action estimate.

## Numerical and semantic gates

Both populations require:

- exact geometry, source rank, feature width, work, and allocation identities;
- complete warm, source-refresh, query-only, and adjoint literal-byte identity;
- the same 16 source sample and eight query sample derivation as ADR-0373;
- source sample absolute error at most `2e-12`;
- direct-query absolute/relative error at most `2e-8` / `2e-11`;
- affine sample absolute error at most `2e-10`;
- streamed forward/transpose dot absolute/relative error at most `2e-8` /
  `1e-10`;
- complete 10-card forward and adjoint agreement with the exact bounded oracle;
- exactly two source-reference chunks at 22 cards and one at 10 cards;
- source and compatible device death before unique-adjoint birth;
- one active unary allocation throughout the forward classes; and
- all raw numbers finite, every observed pool-used value no greater than the
  independently modeled live rows for its phase, and the maximum pool total no
  greater than the modeled bounded device peak.

CUDA event timings may be retained separately for cold, warm, refresh, query,
direct, and adjoint mechanisms, but no timing conjunct selects the result. A
60-second per-population hang guard is infrastructure-only.

## Required adversarial controls

Before source seal, controls must catch:

1. one byte changed in a later host-reference chunk;
2. a missing final chunk or overlapping/gapped chunk span;
3. digest equality substituted for literal comparison;
4. a full device reference copy or full product expression in the source AST;
5. three simultaneous unary variants instead of one overwritten buffer;
6. unique-adjoint allocation before forward-state death;
7. transpose dot against compatible rather than source reference;
8. last query label omitted from the adjoint aggregation;
9. a pool snapshot or ownership transition omitted from evidence;
10. nonzero pool or pinned state after release; and
11. any 16/28/34/40/45-card request or target compiler path before CuPy import.

## Kill criteria

Kill the bounded mechanism if either population fails any exact, numerical,
byte, chunk, ownership, allocation, pool, device-identity, or release gate; if
22 cards does not cross the 64-MiB seam; if target code becomes reachable; if
an observed used/high-water value exceeds its prospective bounded model; if an
unnamed device temporary is required; or if any tolerance, population, chunk,
repetition, or claim changes after the first real device observation.

A bounded pass authorizes only a separately preregistered and source-sealed
one-shot literal-target owner. It does not authorize calling 45 cards directly.
A bounded rejection does not authorize truncation.
