Thirteen new tests pass. They cover exact 10/22 geometry and work, mandatory
two-chunk coverage, later-chunk byte mutation, gap/overlap/missing spans,
digest non-authority, no full device reference or product, one active unary,

The first pre-seal device run rejected only `exact_work_identity`. The new
ledger had counted 63 nonempty subsets for each six-card reverse target. The
four-card recurrence reads the empty subset and every subset of sizes zero
through four: `sum(C(6,k), k=0..4) = 57`. The sealed ADR-0373 ledger and kernel
both already used 57. The prospective formula was corrected from 63 to 57;
the 10/22 reverse scalar-addition counts are 1,532,160 and 544,376,448. No
kernel, array, tolerance, population, chunk, repetition, result, or claim
changed. The rerun passes all gates. This is retained as a pre-seal work-ledger
plumbing correction, not hidden as a favorable scientific relaxation.

The first whole-discovery run then exposed a separate test-harness lifetime
defect: earlier resident-cache test classes retained live bytes in the
process-wide default CUDA pool. The seam passed alone, but correctly failed
`pool_used_within_phase_model` and `release_complete` after those fixtures
because `free_all_blocks` cannot release referenced arrays. Explicit teardown
on the two first identified classes made the narrow 64-test ordering
regression pass, but the next complete discovery still arrived with 3,202,048
live bytes from additional historical and manually nested GPU fixtures. That
second rejection proved per-class cleanup was not a structural boundary.

The final controls therefore invoke the no-argument owner in a fresh `-B`
subprocess and return its complete gates, errors, chunk spans, transition
telemetry, invocation/work ledgers, digests, walls, and claims as JSON to the
parent tests. Both the before-allocation and released snapshots must report
zero pool used and total bytes. A deliberately contaminated chain containing
the leaking sparse-incidence and nested device-fold fixtures now passes all 22
tests because their arrays remain outside the owner's process, not because
they are forgiven. The two explicit fixture teardowns remain as ordinary test
hygiene. The seam source, allocator model, absolute zero-release gate, kernels,
tolerances, populations, chunks, repetitions, outputs, and claims were
