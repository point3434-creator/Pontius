## Global feature contract

Feature width is 176 because the direct automaton has 175 source states and
one reach feature. Global state features are exactly indices 0 through 174;
reach is exactly global index 175. The frozen half-open feature partition is

```text
slice 0     [0, 128)     width 128
slice 1   [128, 176)     width  48
```

The ranges are complete, disjoint, and globally indexed. A slice-local state
number may never be passed to a terminal transition as though it were the
global state. The default execution order is frozen as shown; a bounded
control must also process the ranges in reverse order to prove that the
mathematics, rather than that order, determines the recombined result.

The quotient is column-separable, so forward and transpose may operate on
either range independently. Fold semantics require more care: state columns
contribute partial numerator, while the sole reach column contributes reach
and the sunk affine term. Reach therefore belongs only to slice 1. Partial
numerators and reaches are accumulated across both slices and normalized only
once afterward. Producing or comparing per-slice conditional values is a
semantic error, not a numerical approximation.

The maximum physical feature workspace is 128 columns. Slice 1 is a
nonadditive 48-column active view of that workspace, not a second 128-column
allocation. A source seal must account separately for logical active width and
physical allocated width: bytes use the 128-column maximum, while semantic
work uses exactly 128+48 columns, never 256.

## Streaming and semantic chunk ownership

The forward path uses chunks of 65,536 labeled query records. It signs one
chunk from the width-128 recurrence, folds that chunk into numerator and reach,
and consumes the scalar contribution before reusing the chunk buffer. No full
893,970-by-slice compatible matrix is allowed.

The adjoint cannot reuse that chunk integer as an accidental universal knob.
Its first semantic unit is a complete six-label query occupancy. It therefore
uses 10,922 occupancies, or 65,532 records, per covector chunk. No chunk may
split an occupancy before label aggregation into the four-card recurrence.
The signed source output uses 32,768 six-card occupancies and must be consumed
before reuse. Full query-covector, full unique-source-adjoint, and 90-fold
record-expanded adjoint arrays are forbidden.

This separation structurally retires one more instance of the recurring
semantic-quantity/numerical-coincidence defect family: forward record count,
adjoint occupancy count, and source occupancy count have different types even
when an implementation might otherwise represent all three as integers.

## Exact lifetime model

The config freezes twelve ordered phases from `host_bridge` through
`release`, and thirteen typed lifetime classes. Three parent-derived bridge
classes must expand back into every named NumPy shape/dtype row before the
phase sweep; their byte totals are cross-checks, not aggregate authority. The
source seal must independently derive every physical shape and dtype, then
compute phase totals only by sweeping row birth and death. It may not use a
favorable closed-form peak in place of that sweep.

Host bridge residency is inherited exactly from ADR-0386: 15,888,996 bytes of
consumer-resident NumPy payload plus 84,972 bytes of separately retained
validation payload. The 79,216-byte warm-mutable view remains nonadditive.
Device consumer residency mirrors only the named consumer payload and adds one
seven-entry `int64` cardinality-offset row. Equal byte counts do not merge host
and device ownership.

The largest forward physical row is the
`9,531,040 x 128` Float64 recurrence workspace. The source coefficients are a
view of its six-card level, not another allocation. The compatible,
numerator, and reach rows are bounded forward chunks. After both feature
slices fold, every forward workspace must die before any adjoint workspace is
born.

The adjoint owns one `164,221 x 128` Float64 recurrence, one complete-label
covector chunk, and one bounded unique-source chunk. Aggregated four-card
covectors are written into the four-card level of the adjoint recurrence, not
duplicated in a second full array. A single explicit 67,108,864-byte shared
scratch allowance is named. Allocator pools, context/module storage, registers,
local memory, page tables, Python objects, and unrelated process activity stay
named exclusions rather than hidden zeroes.

The fixed arithmetic gates remain 48,000,000,000 host numeric bytes,
12,000,000,000 device numeric bytes, 8,000,000,000 and 2,000,000,000 byte
reserves, and minimum 60 GB/16 GB physical capacities. Passage of those source
inequalities is not live admission. A future device owner must observe

## Bounded independent differential

The source successor must use the complete ten-card occupancy population but
an engineered rank-175, width-176 column payload. This is a seam control, not
a ten-card poker automaton or a natural result. One independently written
monolithic exact oracle uses `Fraction` arithmetic over all 210 six-card
occupancies, 210 four-card occupancies, and 1,260 labeled query records. The
sliced implementation may not call the oracle's partition or recombination
helpers.

The control must prove exact monolithic-versus-sliced forward rows, folded
numerator and reach, adjoint rows, and transpose dot identity. Features 0,
127, 128, 174, and 175 must all carry detecting mass. It must also prove
reverse slice-order identity, forward-record partition invariance, complete-
occupancy adjoint partition invariance, source-output partition invariance,
and normalize-after-recombination identity. Any supplementary Float64 view
uses the unchanged `2e-11` absolute envelope; exact identities remain exact.

The legal meaning of the parent bridge remains covered by ADR-0386's reduced
settlement/open-mode/leaf-adjoint controls. This new synthetic control tests
only the new feature, streaming, and adjoint seam; it must not relabel itself
as additional poker-context evidence.

## Adversarial controls and kill criteria

Reject the source seal on any dependency, bridge, topology, or config digest
drift; missing, overlapping, reordered, or slice-local feature identity;
duplicate or missing reach; per-slice normalization; an adjoint chunk that cuts
one six-label occupancy; reuse of one untyped chunk knob across forward and
adjoint; forward/adjoint co-residency; an omitted, duplicated, unit-confused,
or shape-times-itemsize-inconsistent lifetime row; or a cap/reserve failure.

Controls must deliberately mutate both sides of the 127/128 boundary, reach
ownership, a label-group boundary, one lifetime unit, one birth/death edge,
one bridge identity, and one allocation size. Every mutation must reject for
its intended reason. The cap guard must reject before any CuPy import.

Any CuPy import, device call, actual 45-card forward/fold/adjoint value,
literal-target owner import or call, resolver or master iteration, action,
15-second comparison, quality label, truncation selection, blueprint work, or
poker-strength field inside this boundary kills it rather than widening the
claim.
