## Decision

### Exact failure and independent diagnosis

After both families released, `_population_evidence` called ADR-0394's
`_pair_error_evidence`. Its first source authority is generated by ADR-0394
`sample_rows`, which freezes sixteen source ranks and sixteen labeled query
records per calibration population. The generated execution runner did not
capture that helper. `build_generated_population_runner` copied
`vars(legal_river_quotient_cuda_compensated_tiles)`, so the generated
`_run_device_population` resolved the older parent `_sample_rows`: at
population 10 it selected seven source ranks and seven query records.

The source comparison therefore flattened seven rows times eight boundary
features into 56 actual pairs while constructing sixteen rows times eight
features, or 128 expected pairs. `_maximum_pair_errors` rejected before reading
a value. A source-only adversarial reproduction inspected the compiled
function's globals and proved the bound helper is exactly the parent helper,
not the evidence helper, with lengths `(7, 7)` versus `(16, 16)`. This matches
the retained exception and is independent of numerical values.

This is a plumbing/schema defect: two same-shaped callable concepts named
`sample_rows` carried different frozen populations. It is another semantic
quantity hidden behind a compatible Python signature. The structural repair is
one immutable sample-plan object consumed by execution and evidence, with
identity and cardinality checked before device work—not merely changing one
dictionary assignment.
