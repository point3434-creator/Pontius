## Exact fixed-point capture

Every finite nonzero binary64 component has one canonical form
`m * 2^e`, where `m` is an odd signed integer. For each complete semantic
family—source rows, labeled query covectors, and labeled query weights—the
family exponent is the smallest canonical `e` among every nonzero high and low
component. An all-zero family uses exponent zero. Each pair is encoded by
left-shifting both component mantissas to that family exponent and adding them
as signed integers. There is no rounding.

The exponent is global to the complete family, not selected per feature tile,
chunk, or traversal. Otherwise separately scaled tile totals could be compared
or added as though their integer units matched. A future runtime must either
derive the exponent from immutable provenance before capture or charge a
complete scan and any required replay. A warm value below the cached exponent
forces a cold rebind; shifting it away is forbidden. Every future fixed-limb
config must freeze its own admitted component-exponent window before source,
then reject any nonzero component outside that inclusive window before integer
arithmetic begins. Synthetic controls accept both exact edges and reject one
binary-exponent step beyond each. That conditional admission turns the later
limb calculation into a theorem without promoting the old ten-card window.

Positive and negative Float64 zero both encode semantic integer zero. NaN and
infinity reject. Signed nonzero inputs are supported because cancellation and
negative payoffs are part of the required evidence, even though the current
source belief rows are nonnegative.

## Division-free forward algebra

Let `S[M]` be one encoded six-card source-occupancy feature and define the
ordinary containment marginal

```text
Z6[T] = sum_{M superset T, |M|=6} S[M].
```

Instead of the divided recurrence, build

```text
G6[M] = S[M]
Gk[T] = sum_{x notin T} G(k+1)[T union {x}].
```

Induction gives `Gk[T] = (6-k)! * Z6[T]`: every six-card superset
of `T` appears once for each ordering of its remaining `6-k` cards. Multiplying
the disjointness output by `6! = 720` therefore yields the integer expression

```text
Y720[L] = sum_{T subset L} (-1)^|T| * w6[|T|] * G|T|[T]
w6[0..4] = {1, 6, 30, 120, 360}
         = 720 / (6-k)!.
```

Hence

```text
Y720[L] = 720 * sum_{M: M & L = 0} S[M].
```

There is no recurrence division and no rounded intermediate. Every bounded
`Y720` row must be exactly divisible by 720, although the implementation may
retain the scaled integer rather than divide it.

## Division-free adjoint algebra

First sum the six labeled query covectors that share each four-card occupancy:

```text
Q4[L] = sum_{record: occupancy(record)=L} C[record].
```

Define

```text
H4[L] = Q4[L]
Hk[T] = sum_{x notin T} H(k+1)[T union {x}].
```

Now `Hk[T] = (4-k)! * Z4[T]`. The same global scale 720 is legal,
but the coefficient vector is necessarily different:

```text
A720[M] = sum_{T subset M, |T|<=4} (-1)^|T| * w4[|T|] * H|T|[T]
w4[0..4] = {30, 120, 360, 720, 720}
         = 720 / (4-k)!.
```

Therefore

```text
A720[M] = 720 * sum_{L: L & M = 0} Q4[L].
```

The proposal's original `{1,6,30,120,360}` vector is correct for the six-card
forward recurrence and wrong for this four-card adjoint recurrence. Copying it
across the seam is a required rejecting mutation. This is the semantic-
quantity-behind-a-numerical-shape defect family in a new costume: both arrays
have five small integers, but they encode different factorial depths.

For every feature,

```text
NF = sum_L Y720[L] * Q4[L]
NA = sum_M S[M] * A720[M]
NF = NA = 720 * sum_{M,L: M&L=0} S[M] * Q4[L].
```

Normal, reverse, chunked, tiled, and permuted traversals must produce the same
integers. Exact associativity makes traversal order irrelevant only after
overflow has been excluded.

## Reach and the one terminal rounding

The six labeled query weights are aggregated identically into `W4[L]`. The
exact scaled reach integer is

```text
RF = sum_L Y720[L, reach] * W4[L].
```

It must be positive. If the source, covector, and weight family exponents are
`qS`, `qC`, and `qW`, respectively, the exact conditional chip value is

```text
(NF / RF) * 2^(qC-qW).
```

The common 720 and `qS` cancel. The terminal is therefore not generally
"divide by 720 as a Float64." It is one exact rational-to-binary64 conversion.
The implementation must locate the binary exponent by integer comparisons,
use integer `divmod`, compare twice the remainder with the denominator, apply
round-to-nearest/ties-to-even, handle a significand carry into the next binade,
and pack the binary64 bits. Normal, subnormal, zero, minimum-normal, negative,
and overflow paths are explicit. An exact zero returns positive zero;
nonpositive reach and overflow reject. No host floating-point comparison may
decide rounding.

## Signed bounds and guard limbs

Let `BS`, `BC`, and `BW` be the maximum absolute encoded entries of one source
row, one labeled query covector, and one labeled query weight. For `n`
available cards, the keystone must independently derive and check:

```text
BG(k) = (6-k)! * C(n-k, 6-k) * BS
BY     = 720 * C(n-4, 6) * BS
BYwork = sum(k=0..4) C(4,k) * 720/(6-k)! * BG(k)

BH(k) = 6 * (4-k)! * C(n-k, 4-k) * BC
BA     = 720 * 6 * C(n-6, 4) * BC
BAwork = sum(k=0..4) C(6,k) * 720/(4-k)! * BH(k)

BNforward = C(n,4) * F * BY * (6*BC)
BNadjoint = C(n,6) * F * BS * BA
BR        = C(n,4) * BY * (6*BW).
```

`BNforward` and `BNadjoint` must be exactly equal by
`C(n,4)C(n-4,6) = C(n,6)C(n-6,4)`. Final-result bounds do not replace the
larger signed partial-sum bounds inside inclusion-exclusion.

For a symmetric absolute bound `B`, the required signed width is one bit when
`B=0`, otherwise `B.bit_length()+1`. A fixed-width candidate requires the
ceiling in 64-bit limbs **plus one guard limb**. The semantic authority is an
unbounded signed integer; a fixed-width emulator must agree and prove the
guard is unused. One-limb-short, carry-into-guard, long-cancellation, and
negative-accumulator controls are mandatory. A guard is spare capacity, not
permission to omit products, term counts, signs, or carries from the proof.

ADR-0393 observed complete-ten stored component `frexp` exponents from -145
through 11. As a reporting-only conservative calculation, that permits a
component quantum of `2^-198`, a captured-pair integer magnitude below
`2^210`, forward and adjoint table work requiring at most 245 and 241 signed
bits, and therefore four mathematical table limbs plus a fifth guard. The
complete numerator bound is 480 signed bits and reach is 473: eight
mathematical scalar limbs plus a ninth guard. Thus "five limbs" is plausible
for table cells under that old envelope, not for the scalar and not for an
unseen population. The nine guard-inclusive scalar limbs are 72 live bytes if
one thread holds the accumulator. Their eventual placement is unselected: a
later compiled-device gate must report registers, local bytes, and spill-load/
spill-store bytes and explain every limb. No population-25 or actual-context
exponent or resource claim follows.

The rejected five-limb forecast is a named instance of a recurring defect:
**value-window reused as product/accumulator window**. A captured value and a
global bilinear accumulator may share an integer encoding, but their magnitude
bounds are different semantic quantities. The product combines both operand
floors and the accumulator additionally carries the complete term count.

## Fixed-side and delta hypotheses

If captured source rows are invariant for a solve, the forward transform may
be built once; if captured query rows are invariant, the adjoint may be built
once. "Invariant" includes values, topology, feature mapping, family exponent,
and limb admission.

An exact changed six-card source row contributes directly to 57 stored subsets
through level four; a changed four-card query occupancy contributes to 16.
Compared only with recurrence edges, the corresponding floor break-even counts
are 975,784 source occupancies and 40,035 query occupancies. Capture, label
aggregation, scalar contraction, and dirty-set discovery stay separate. One
changed source hand can affect `C(43,4)=123,410` occupancies, but that is not a
prior on solver update density.

Delta maintenance is eligible only with an exact dirty set, fixed exponent and
limb admission, unchanged topology and opposite side, and exact identity with
a cold rebuild. A new lower exponent, unknown or dense change, or changed
opposite side forces cold rebuild. Exact subtraction eliminates arithmetic
drift only after those semantic preconditions pass.

## Kill criteria

Kill the mechanism if captured-pair exactness is presented as original-factor
exactness; one coefficient vector is used for both recurrences; any division or
Float64 rounding occurs inside the operator; any signed partial, product,
term-count, carry, or guard bound fails; a value/table window is reused as a
product/accumulator window; a fixed-limb run lacks prospective exponent-window
admission; the old ten-card exponent envelope is
promoted to 25 or 45 cards; fixed-stride memory is claimed to shrink without a
new layout; sparse delta runs without every typed precondition; or headline
integer throughput substitutes for multi-limb work and measured device wall.

A CPU failure closes this mechanism before CUDA. A CPU pass authorizes only a
separate prospective fixed-limb/device-work preflight. It does not authorize
population 25, an actual owner, or a resolver call.
