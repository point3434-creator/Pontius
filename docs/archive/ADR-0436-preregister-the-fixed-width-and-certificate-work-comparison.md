## Positional candidate

The positional representation uses signed little-endian two's-complement
64-bit limbs. For each independently derived semantic bound, the mathematical
width is `ceil(required_signed_bits / 64)` and the allocation adds one guard
limb. The guard must remain only exact sign extension after every named
operation. It is not spare permission for an omitted partial, product, term
count, carry, or borrow.

Addition, subtraction, negation, signed small-constant multiplication, and
full multiplication are limb algorithms, not Python integer shortcuts in the
candidate path. Signed products extract exact magnitudes, use unsigned
schoolbook products including every high half and carry, then restore the sign
inside the separately sized destination. Reduced controls compare every
operation and operator output with unbounded integers. One-limb-short, a
non-sign guard, long carry, long borrow, negative minimum, cancellation, and
product-window mutations must fail.

The old diagnostic profile prices captured entries at 211 signed bits, the
largest table/partial at 245, and the largest scalar at 480. It therefore uses
four mathematical plus one guard table limbs and eight mathematical plus one
guard scalar limbs. These are conformance dimensions over already-open
controls, not population-25 or actual-45 promises.

## RRNS candidate and its exact claim

The RRNS representation freezes eight ascending working primes below `2^62`
and one distinct redundant prime larger than all eight. The first four working
primes plus that common redundant prime form the table code; all eight working
primes plus the redundant prime form the scalar code. Their exact products are
immutable config fields. Primality uses the frozen deterministic unsigned-64
Miller--Rabin basis set, with exact small-prime, pairwise-GCD, and witness
controls before operator work. Every channel carries the same scaled integer
modulo its own prime through identical operator arithmetic. Each working
product is odd, so its signed representative is unambiguously
`[-(M-1)/2, +(M-1)/2]`.

The source-seal bound is derived before telemetry from the three frozen
canonical exponent windows, the binary64 mantissa ceiling, and a conservative
12-card/176-feature control geometry. It yields exact 211-bit maximum table and
405-bit maximum scalar requirements. The table and scalar working products are
248 and 496 bits, respectively. Eligibility is decided by the checked integer
inequality `M >= 2B + 1` over the exact derived `B`, not those bit lengths. The
old measured-envelope diagnostic happens to be wider at 245/480 bits and is
retained only as comparison geometry; it is not the detection theorem's bound.
Signed CRT returns the unique symmetric representative and rejects anything
outside the matching frozen semantic bound. A changed admission window changes
`B` and forces this proof to run again before operator work.

One redundant channel supports one deliberately narrow theorem. If all errors
are confined to one named channel, the final residue at a checked site is
changed, the decoder and other channels are correct, `M >= 2B + 1`, and
`m_R > max(m_i)`, then the corruption cannot pass either frozen check.

The full-CRT form reconstructs all channels. Its difference from truth is a
nonzero multiple of the product of the uncorrupted channels. That product is
at least `M`, so the corrupted reconstruction cannot remain in `[-B,B]`. The
cheaper base-extension form reconstructs the working channels, rejects outside
`[-B,B]`, predicts the redundant residue, and compares it with the carried
one. For a changed working channel `j`, the decoded difference is
`t*(M/m_j)` with `0 < |t| < m_j`; a false redundant match would require
`m_R` to divide `t`, impossible because `m_R > m_j`. A redundant-only change
mismatches directly. Both forms must be implemented and agree on injected
faults; a future run freezes one before operation.

Multiple errors inside the same channel are covered only when their composed
final residue differs. Errors that cancel modulo that channel leave no wrong
checked residue and are not called detected faults. There is no claim about
two-channel faults, correlated faults, decoder faults, or a common algorithm
defect. A deliberately consistent wrong in-bound integer encoded across every
channel must pass RRNS and fail the independent unbounded differential; that
control proves the fault-model boundary rather than pretending RRNS can see it.
Every channel is also mutated at zero, signed, and bound-edge controls.

The operator remains scaled by 720 throughout residue arithmetic. It
reconstructs the integer before checking divisibility. No config constant or
executed operation may have the semantic role of a modular inverse of 720 or
one of its factors, because that would erase the checksum. This is a semantic
provenance rule, not a ban on an unrelated integer with the same numerical
encoding. Device-form modular multiplication is prospectively specified as
64-bit Montgomery arithmetic with `R=2^64`, exact low/high halves, explicit
carry, and a bounded conditional subtraction. A truncated `uint64(a*b)` is
not a reduction.

Every integer reconstruction site executes its frozen check. A detected
inconsistency terminates as `rrns_channel_fault_detected`, with no retry,
silent recomputation, or correction. Intermediate cells are not reconstructed
merely to range-check them; their legitimate values remain governed by the
separate keystone width proofs.

Two RRNS schedules are priced without choosing between them: retain all nine
table channels, or retain the first five and recompute the recurrence for the
remaining four channels when scalar residues are required. The latter may not
hide base extension or recurrence replay. Every edge, load, store, conversion,
and residue operation remains charged.

## Selective work, global closure, and physical storage

At literal 45-card geometry, `G` construction contains 55,619,730 vector edges
and `H` construction 640,575. Once built, a selected query reads 16 subset
rows and a selected source reads 57. Across width 176 those are 2,816 and
10,032 feature entries, respectively.

Complete scans are categorically different. All forward query coordinates
contain 419,569,920 subset-feature entries and 26,223,120 scalar products. All
adjoint source coordinates contain 81,711,241,920 subset-feature entries and
1,433,530,560 scalar products. A certificate may stream these coordinates and
retain only a frozen chunk. The work remains global; the allocation does not.

Approximate arithmetic may propose warm iterates, rows, columns, or a basis.
Final authority must reconstruct exact primal and dual objects, check complete
primal and dual feasibility and the frozen exact objective/gap relation, and
then establish global separation/pricing or a conservative exact bound over
every omission. A reporting tolerance cannot decide closure. ADR-0436 freezes
this consumer contract; it does not implement the full resolver certificate.

## Colex traversal and table alternatives

For sorted zero-based cards, colex rank is
`sum_i C(card_i, i+1)`. If card `x` is inserted at position `j` into parent
`t`, the child rank is

```text
sum_{i<j} C(t_i,i+1) + C(x,j+1) + sum_{i>=j} C(t_i,i+2).
```

A row owner may unrank once, build its prefix and shifted-suffix constants,
visit children in ascending card order, and advance the insertion position at
most `k` times. Each child then needs one binomial lookup and bounded integer
adds. This is amortized constant work only within that sequential row owner;
it is not constant-time random unranking for unrelated threads.

The source seal compares that path with resident rank/card, mask, and adjacency
tables. It retains the exact 48,870,360-byte source-card table,
65,160,480-byte source-mask table, and 222,478,920-byte forward adjacency cost
as distinct alternatives. Exhaustive `n=10` and `n=12` child ranks plus frozen
literal-45 boundary parents must match independent enumeration.

## Telemetry, work, and source-seal exit

Every captured family reports stored-component `frexp` extrema for description
and canonical odd-mantissa exponent extrema for admission. They are separate
fields for source rows, covectors, and weights, with high/low, sign, zero, and
subnormal counts. `frexp` may not admit, reject, size, or select anything. An
all-zero family has null nonzero extrema and family exponent zero.

The work ledger reports loads, stores, word/carry work, wide products,
small-weight products, modular additions and reductions, CRT/base-extension
work, colex work, redundant checks, and recurrence replay separately. It does
not add heterogeneous operations into pseudo-time or divide them by vendor
peak throughput. The later device gate must compile both eligible candidates,
report registers, local bytes, spill loads/stores, and measured contiguous
phase walls before making any speed or fit claim.

The source seal reuses only ADR-0435's already-open complete-ten and signed-
twelve populations. It also checks exact primes, CRT uniqueness, the bounded
single-channel theorem, Montgomery arithmetic, 720 divisibility, positional
guards, selective-versus-dense reduced outputs, streamed complete-domain
accounting, colex ranks, telemetry, and literal-45 formulas. Population 25 and
actual-45 numerical values remain forbidden.

During drafting, one nonauthoritative shell one-liner reproduced R183 by
hashing a literal backslash-r/backslash-n rewrite. It was discarded before the
config existed. The recorded config digest was derived with explicit CR/LF
byte values and agreed with an independently written byte loop. The source
