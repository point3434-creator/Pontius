## Exact pre-allocation boundary

The current topology compiler recursively materializes every compatible
assignment inside each three-seat half, then stores UInt64 union masks, Int32
hand indices, and forward/reverse inclusion-exclusion ID/sign tables. Before
calling that compiler, `full_width_factor_tt_capacity` computes the exact
persistent numeric-array bill from semantic record counts:

- a half with `k` complete opponent axes over `n` available cards has
  `product(C(n - 2*i, 2), i=0..k-1)` labeled compatible records;
- one half record owns one UInt64 mask and one Int32 index per seat;
- each three-seat record owns 64 subset entries in each relevant source or
  query table; and
- the resident belief cache owns the mixture, both component-product tables,
  and both half-index tables.

The model is exact for those persistent arrays and is deliberately called a
lower bound on live memory. It excludes Python list/set/dict overhead,
construction temporaries, sparse CPU/GPU operators, workspaces whose incidence
cardinality is not yet available, automata, tensor trains, results, and
contraction scratch. No excluded term may be inferred to be zero.

Report both the frozen seat-order base topology and an optimistic scalar
topology obtained by placing the singleton on the more favorable half. The
optimistic cross-check prevents an unfortunate hero/split placement from
masquerading as the whole defect. Resident work requires the bidirectional
topology and separately reports the exact resident-belief lower bound.

Target allocation is admitted only if every necessary lower bound is under its
fixed numeric cap and also preserves its fixed reserve against live physical
headroom:

- at most 48,000,000,000 persistent host numeric bytes;
- at most 12,000,000,000 resident-belief device bytes;
- at least 8,000,000,000 live host bytes beyond the bidirectional topology; and
- at least 2,000,000,000 live device bytes beyond the resident belief.

Crossing any one bound is a complete typed
`representation_rejected_before_target_allocation` terminal. It must execute
zero literal topology builds, scalar contractions, priming contractions, and
warm contractions. Clearing the necessary bounds permits the allocation; it
does not convert a lower bound into a peak-memory certificate. Actual object
bytes, process peak working set, CuPy pool high-water bytes, physical free
memory, construction wall, priming wall, and warm wall are then recorded.

## Decision branches

- **Pre-allocation rejection:** accept that the current explicit-half-
  assignment FactorTT representation does not fit this literal target under
  the frozen workstation caps. Begin a separately preregistered representation
  successor. Do not infer that full-width poker itself is infeasible.
- **Warm path completes within 14,000 ms:** accept only one full-width resident
  leaf-contraction capacity result. A complete solver/action-clock bridge still
  requires its own gate.
- **Warm path completes late:** retain the representation result but reject the
  current warm-contraction action-capacity branch.
- **Typed failure:** retain it, diagnose from the frozen terminal, and do not
  retry this owner.

No branch automatically authorizes certified support truncation. Truncation
must first define an exact discarded-mass/value certificate and earn a separate
preregistered gate. A representation failure triggers that research question;
it does not answer it.
