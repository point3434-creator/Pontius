ADR-0368 quotient has a complete bounded layout on the frozen 45-card river
fixture, without allocating the target or converting a memory result into a

The model must preserve the target-specific validity precondition. For every
one-seat pass the requested open seat is permuted onto the query/right half.
The source is always three fully summed opponent seats occupying six variable
cards. The query is the fixed controlled hand plus two labeled opponent pairs;
after safely projecting the fixed hand, its variable occupancy has four cards.
Seat-specific weights and payoff features enter before source aggregation.

## One operator, not two fixed splits

The deployment-shaped forward matrix is

```text
A[labeled four-card query record, six-card source occupancy]
    = 1 iff the two occupancies are disjoint.
```

Its adjoint is the exact transpose of this same matrix. A target-specific pass
does **not** place an open seat into a four-card source merely to reuse the old
fixed split, and it does not persist a 733,055,400-record six-card open-query
axis. Such a layout would violate ADR-0367 before memory is considered.

Forward and adjoint work must nevertheless be priced separately. The adjoint
first sums its 893,970 labeled query covectors by four-card occupancy, applies
the transposed containment transform, and may stream any required expansion
over the 90 source-seat labelings. The 733,055,400 labelings remain logical
work; they never become a persistent topology.

## Frozen geometry and scalar layout

The source seal must rederive, rather than copy as unexplained constants:

```text
source occupancies                 C(45, 6) =   8,145,060
source labeled pairings            * 90     = 733,055,400
query occupancies                  C(45, 4) =     148,995
query labeled pairings             *  6     =     893,970
containment keys through width 4              =     164,221
forward subsets per source                         57
forward signed terms per query                     16
adjoint subsets per four-card occupancy             16
adjoint signed terms per six-card occupancy         57
```

Combination-ranked source occupancies and containment keys are implicit. The
model may allocate no source-mask table and no sparse incidence matrix. The
rank is a cardinality offset plus an exact colexicographic combinadic rank.
`uint32` is required for occupancy ranks, `uint64` for card masks, and `int32`
for hand indices. The full labeled query topology is retained as one card mask
and two hand indices per record. Binomial and local 90-pairing templates are
small immutable tables and must still be counted.

The proposed execution is streamed. Freeze source chunks at 32,768 occupied
masks and query chunks at 65,536 labeled records. A source chunk may hold a
dense feature row per occupancy; only one chunk exists at a time. The global
containment table is dense in feature width. A query chunk may conservatively
materialize its payoff-state rows and compatible feature rows. Source and
query phase scratch are mutually exclusive, so peak is the larger phase plus
shared resident arrays, not their impossible sum.

## Feature widths

Feature width is semantic, not the old 384-column batching knob. For each
structured-showdown term and mixture component, the source contributes one
coefficient for every state reachable after the three closed source seats and
one reach coefficient. The sunk affine payoff is folded from that reach and
therefore does not receive a duplicate column. For source state ranks `r_t`
and component count `c`, the width is

```text
F = c * sum_t (r_t + 1).
```

Pre-seal static reconnaissance, excluded from evidence, found 59 distinct
opponent strength codes on the frozen `Ks Td / 2c 7d 9h Js Qc` fixture and a
candidate rank trace `59, 117, 175, 4, 5` after target-specific ordering. The
source seal must derive that trace independently and reject if it differs.
The one-term, one-component fixture therefore expects `r = 175` and `F = 176`.

The model must also report a safe feature-only envelope, not call it an
observed poker state. With at most 990 opponent hand indices, three closed
source seats can reach at most `3 * 990 = 2,970` `(maximum, multiplicity)`
states, so the one-term, one-component width is at most 2,971. This bound does
not claim attainability or clock feasibility and does not replace future
board-population testing.

## Arrays and placement

Every byte row must name its dtype, shape, phase, and placement. At minimum:

- deduplicated opponent/controlled hand masks and strength codes;
- mixture and all seat unary weights;
- per-term mode factors;
- target-specific structured-showdown transitions, terminal values, and state
  metadata;
- the labeled query masks and two query-hand index arrays;
- combination offsets, binomial values, and local pairing template;
- dense containment marginals;
- one source coefficient chunk or one query payoff/compatible chunk;
- full labeled query numerator/reach records and final per-hand values; and
- any host staging or retained result arrays.

The structured automaton is consumed directly. Allocated tensor-train storage
must therefore be exactly zero. The model must separately report the dense
one-hot tensor-train export bytes that are forbidden by this layout, so
"tensor train omitted" cannot mean "tensor train forgotten."

Python objects, allocator fragmentation, CuPy pool retention, CUDA context and
module storage, driver state, kernel code, registers/local memory, page tables,
and OS activity are excluded non-numeric classes. They must be named, not
silently rounded to zero. Fixed caps and reserves remain unchanged:

```text
host persistent numeric cap       48,000,000,000 bytes
device peak numeric cap           12,000,000,000 bytes
host free reserve                  8,000,000,000 bytes
device free reserve                2,000,000,000 bytes
minimum physical host/device      60 GB / 16 GB
```

A source-only passage requires both numeric caps and the corresponding
minimum-physical-capacity reserve inequalities. A later live gate must repeat
admission against contemporaneous free memory; this ADR cannot supply it.

## Logical work and refresh

Bytes and work are independent ledgers. The forward ledger must report source
pairing visits, state/reach coefficient accumulations, containment vector
additions, signed query vector terms, query payoff folds, and hand reductions.
The adjoint must report labeled-query aggregation, four-card containment
updates, six-card signed terms, and streamed source-label expansion. No count
may hide a feature-width multiplier.

A source-seat unary change is a **full coefficient and containment rebuild**
under this model. Its topology is warm, but its arithmetic is not incremental.
A query-only unary change may reuse source marginals and redo only query-side
work. Both cases must be distinct. Cold source construction and topology-
stable source refresh must have equal semantic work counts. Any later delta
algorithm is a separate optimization behind cold identity.

No logical operation count is converted to milliseconds. In particular, a
memory pass with tens of billions of irregular Float64 additions leaves the
14,000 ms compute question unresolved. Throughput needs a separately sealed
GPU keystone with frozen numerical tolerances and reduced exact differentials.

## Controls and kill criteria

The source seal must fail if any of these controls fail:

1. every combinatorial count and multiplicity above rederives exactly;
2. combinadic rank/unrank is exhaustive and collision-free on bounded
   universes and passes full-width boundary/sample round trips;
3. bounded forward and adjoint layouts agree with ADR-0368's exact oracle;
4. target-specific ordering puts the open target on the query side and derives
   the frozen showdown rank trace;
5. every array byte equals shape times item size and every aggregate is an
   exact sum of named rows;
6. no persistent labeled source table, sparse incidence, compatible matrix, or
   tensor-train allocation appears;
7. fixture and safe feature-envelope numeric peaks pass both fixed caps and
   minimum-capacity reserves, or the layout is rejected before runtime source;
8. forward, adjoint, cold, source-refresh, and query-only work remain separate;
9. changing chunk sizes alters scratch only, never semantic counts; and
10. every claim remains systems-only and support truncation remains absent.

Kill the concrete layout if it requires a persistent 733,055,400-record axis,
if target-specific permutation cannot keep all open axes out of the source, if
implicit combination ranks collide, if a required array is omitted, or if the
fixed byte/reserve gates fail. Do not kill it merely because the unmeasured
work appears large; record that as the binding throughput risk for the next
gate.

## Claims boundary

This ADR freezes a model before its implementation. It contains disclosed
static arithmetic, not a retained capacity result. Even a later passing source
seal would establish only a complete numeric-array proposal and logical-work
bill for one frozen river fixture plus one safe width envelope. It would not
establish a GPU implementation, live-memory admission, numerical accuracy,
warm latency, CFR iteration, solve, complete 15-second action, decision
quality, support-truncation certificate, or poker strength.
