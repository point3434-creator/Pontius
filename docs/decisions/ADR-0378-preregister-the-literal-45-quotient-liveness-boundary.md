## Question

Can the exact quotient's literal 45-card production state and its independent
validation be scheduled under the workstation's fixed numeric caps without
changing the operator, hiding a temporary, or allocating the target before the
lifetime proof exists?

## Decision

Preregister one CuPy-free source model. It must derive the exact 45-card host
and device lifetimes from named arrays and an ordered phase schedule. It may
implement bounded pure-reference chunk controls. It may not import CuPy, add a
45-card branch to the staged runner, compile target topology, allocate a target
array, emit CUDA source, time a device, or open a result artifact.

ADR-0377 is authoritative only through 40 cards. Its passing curve motivates
this question but supplies no favorable 45-card prior. The retained v1 and v2
staged owners are permanently consumed, and their source remains unchanged.
The new boundary changes validation residency only. The source-coefficient,
cardinality-recurrence, signed-query, affine-fold, and unique-adjoint operators
remain exactly the ADR-0372/ADR-0374 mechanisms.

## Typed lifetime schedule

Every numeric row has a semantic role, placement, dtype, exact shape, birth
phase, and last-live phase. Equal byte counts do not merge roles. The ordered
phases are:

1. `host_topology`: construct only host topology and immutable coefficients;
2. `forward`: allocate static device rows, the width-128 source recurrence
   table, complete compatible-query rows, numerator/reach, and the frozen CUDA
   library scratch allowance;
3. `forward_reference`: copy the complete source slice, compatible rows, and
   numerator/reach to one reusable host baseline in fixed contiguous chunks;
4. `warm_refresh_query_validation`: rerun forward, source-refresh, and query-
   only lanes in-place, comparing every complete output byte against the host
   baseline chunkwise; the baseline is overwritten only after its preceding
   semantic class has closed;
5. `direct_validation`: retain the independent selected-query scan over the
   source slice; it may not call the recurrence and allocates only selected
   masks, features, and outputs;
6. `forward_dot`: allocate the full deterministic query covector, stream
   products in bounded chunks into explicit partial/scalar scratch, and retain
   only the scalar; no full product array is permitted;
7. `forward_release`: release recurrence, compatible, and scalar-output device
   rows while retaining the host source baseline and query covector;
8. `adjoint`: allocate aggregated queries, the four-card recurrence, and one
   unique source-adjoint output; record-level 90-fold expansion remains logical
   work only;
9. `adjoint_validation`: compare complete unique-adjoint bytes to the reused
   host baseline chunkwise and compute the transpose dot against the retained
   host source baseline using the same fixed chunk partition; and
10. `release`: free every owned host/device numeric row and require later live
    pool checks to return to their pre-owner state.

The validation chunk is exactly 67,108,864 bytes (64 MiB), aligned to Float64.
Chunk spans are increasing, nonoverlapping, complete, and independent of
values. The source seal must prove that changing a smaller bounded control's
chunk size changes only the partition, not copied bytes, comparison outcome,
or mathematical forward/transpose dot inputs.

Repeatability is complete-byte evidence, not a digest-only shortcut. A host
baseline may carry a SHA-256 diagnostic, but acceptance requires literal byte
comparison for every chunk. Only one complete host baseline exists at once;
warm, refresh, query-only, and adjoint groups reuse it in order. Device baseline
copies are forbidden.

## Production and validation boundaries

`production_forward_peak` includes only arrays required to evaluate one exact
forward/source-refresh/query-only pass. `validation_forward_peak` adds the
query covector and the fixed chunk/reduction allowance. `adjoint_peak` follows
the explicit forward release and includes exactly one unique adjoint. Host
reference bytes, device numeric bytes, and excluded allocator/runtime classes
remain separate.

The later model must also report the rejected old-validation counterfactual:
full device forward references, two co-resident unique adjoints, simultaneous
forward/adjoint rows, and a full product temporary. That number is diagnostic
provenance for the scheduling decision, never a gate on the new schedule.

Caps remain unchanged:

```text
host persistent numeric cap       48,000,000,000 bytes
device peak numeric cap           12,000,000,000 bytes
host free reserve                  8,000,000,000 bytes
device free reserve                2,000,000,000 bytes
minimum physical host/device      60 GB / 16 GB
```

The pure source verdict requires exact named-row sums below both numeric caps
and the corresponding minimum-physical reserve inequalities. It is not live
admission. The eventual target owner must recheck contemporaneous free host and
device memory before target allocation.

## Controls

The source seal must pass all of these without CuPy:

1. independently rederive every target combination count, rank, feature width,
   recurrence row count, dtype size, and structured-automaton byte;
2. reconstruct every phase peak by sweeping typed birth/death rows, not by a
   separately coded closed-form total;
3. recover ADR-0374's exact 10/16/22/28/34/40 allocation rows when its old
   lifetime schedule is requested, then distinguish that schedule from the
   new target validation schedule;
4. show production, host-reference, streamed-forward-dot, and adjoint peaks as
   different semantic quantities even if two happen to be numerically equal;
5. prove bounded chunk coverage, order, byte identity, deliberate one-byte
   mutation detection, and partition-size invariance;
6. prove bounded streamed forward and transpose dot inputs equal their
   monolithic mathematical operands, with numerical evaluation left to a later
   prospectively frozen device gate;
7. AST-reject CuPy imports, target allocation/call sites, a full elementwise
   product row, device output-reference copies, record-expanded adjoints, and
   reused semantic-role identifiers;
8. price the complete reusable host baseline, staging chunk, query covector,
   partial reduction scratch, and every static/production/adjoint row;
9. keep fixed numeric passage, physical reserve passage, and future live
   admission as three distinct fields; and
10. preserve null literal-result, latency, action, quality, truncation, and
    strength claims.

## Kill criteria

Kill the proposed schedule if production alone exceeds a fixed cap or reserve;
if any live phase needs both the full forward table and the unique adjoint; if
repeatability requires a full device reference; if a dot path materializes a
full product; if complete byte comparisons are replaced by hashes; if chunk
partition changes operands or acceptance; if the adjoint omits unique-source
or modeled label-write work; if the model imports or calls target device code;
or if an arithmetic passage is called live, timed, actionable, qualitative, or
evidence for truncation.
