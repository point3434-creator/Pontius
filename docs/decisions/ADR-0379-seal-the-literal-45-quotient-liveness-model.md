## Decision

Accept `literal_45_quotient_liveness` as a source-only fixed numeric-lifetime
result. Nine controls pass. The module imports no CuPy, exposes no target
runtime entry, allocates none of its large declared shapes, and computes every
peak by sweeping unique semantic rows over their frozen birth and death phases.
All live-admission and external claim fields remain null or false.

The new schedule passes the 48-billion-byte host numeric cap, 12-billion-byte
device numeric cap, and both minimum-physical reserve inequalities. The device
peak is 11,755,029,796 bytes at `forward_dot`, leaving only 244,970,204 bytes
under the numeric cap. That margin is too narrow to absorb an unmodeled full
temporary and is not authority over allocator fragmentation, cached pool
blocks, CUDA context/module storage, registers/local memory, page tables, OS
activity, or unrelated processes. A later bounded CUDA mechanism must show its
actual allocation graph and high-water before any target owner is allowed.

## Bounded validation controls

Chunk spans are increasing, gap-free, nonoverlapping, complete, and Float64-
aligned. Literal byte comparison passes identical arrays under multiple chunk
partitions and rejects a one-byte mutation. SHA-256 is recomputed invariantly
but remains reporting-only. A signed, non-dyadic, positive-zero, negative-zero
exact `Fraction.from_float` dot oracle returns the same mathematical result for
all tested partitions and rejects a one-ULP operand mutation.

The old schedule's six retained peaks reconstruct exactly, which independently
binds the new arithmetic to the staged geometry. AST controls reject a CuPy
import, staged target executor/compiler calls, NumPy full multiplication,
device reference rows, record-expanded adjoints, and the named
`compatible * query_covectors` product form. Source/compatible rows do not
overlap the unique adjoint, while the host source buffer explicitly bridges
the transpose proof.

The 62-test load-bearing quotient, staged, retained-result, GPU mechanism, and
capacity group passes in 6.903 seconds. This includes nine new liveness tests.
The liveness import check runs in a fresh process, so its no-CuPy conclusion
does not depend on which earlier tests populated the parent interpreter. This
is source/control verification, not target device evidence.

The first whole-repository audit exposed that isolation defect before the
seal: 1,801 tests ran in 902.919 seconds; 1,797 passed, two optional tests
skipped, and two failed. One was the known immutable ADR-0365 pre-invocation
result-absence predicate. The other was the new control's incorrect assertion
that CuPy must be absent from the shared parent interpreter after earlier GPU
tests had legitimately imported it. The control was changed to launch a fresh
`-B` child with an explicit `PYTHONPATH`, assert CuPy absent before importing
this module, import it, and assert CuPy still absent. No liveness row, phase,
cap, margin, chunk, operator, or claim changed.

After that test-only repair, full discovery ran the same 1,801 tests in
900.425 seconds: 1,798 passed, two optional tests skipped, and the sole failure
was the exact known immutable
`test_full_width_river_capacity_preflight_v2.FullWidthRiverCapacityPreflightV2Tests.test_parent_failure_is_exact_and_v2_result_is_absent`
predicate. It still requires ADR-0366's retained v2 result to be absent. No new
regression remains, and the sealed historical test is not edited or waived.

## Claims boundary

ADR-0379 establishes exact combinatorics and a passing named-numeric-array
lifetime proposal for the frozen literal-45 fixture. It does not establish
that actual CuPy/CUDA allocation follows the proposal, that the new streamed
dot meets the old numerical envelope on-device, that excluded memory fits, or
that current free memory admits the target. It supplies no target call,
throughput, CFR iteration, solve, legal action, 15-second decision, decision-
quality gain, support-truncation authority, or poker strength. A fixed source
pass is not a systems result.
