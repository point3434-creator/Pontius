## Live admission and lifecycle

Before any large host reference or device numeric allocation, the future
owner must initialize the fixed CUDA context, synchronize, collect Python
garbage, clear default and pinned pools, and require zero pool used/total and
zero pinned free blocks. It then samples typed Windows host physical/process
memory and CUDA free/total memory. Admission is conjunctive:

1. ADR-0379's exact 9,353,336,216-byte host and 11,755,029,796-byte device
   peaks pass their unchanged 48/12-billion-byte numeric caps;
2. live host available is at least host peak plus 8,000,000,000 bytes;
3. live device free is at least device peak plus 2,000,000,000 bytes;
4. the GPU is exactly NVIDIA GeForce RTX 5080, compute capability 120,
   17,094,475,776 total bytes, CUDA driver 13030, runtime 13020, and CuPy
   14.2.0; and
5. no target numeric allocation or scientific kernel call occurred before all
   four preceding conjuncts were recorded.

A failed admission is a retained `live_admission_rejected` target result with
zero target allocation/kernel calls. It is not an infrastructure failure and
does not authorize a smaller population or truncation.

After admission, the exact 17-transition ADR-0381 ownership schedule applies:
`before_allocation`, forward allocation, cold reference, warm validation,
source-refresh reference/repeat, query-only reference/repeat, direct
validation, query-covector allocation, forward dot, forward release, adjoint
allocation/run/reference/repeat, and final release. Exactly one active unary
is allocated and overwritten twice. Source build, signed query, affine fold,
adjoint, direct-scan, and unary allocation invocation counts remain
`4/6/6/2/1/1`, with two unary overwrites.

Every transition records named ownership, pool used/total, CUDA free/total,
host available physical bytes, process working set, and process private bytes.
Pool used must fit that transition's exact numeric lifetime; pool total must
fit the 11,755,029,796-byte target peak. Allocation failure at any named birth
is a typed `allocation_rejected` terminal carrying the last completed
transition and cleanup evidence. No allocation is retried with another order,
allocator, dtype, width, feature batch, or backend.

Forward device state must die and cached dead blocks must be released before
the aggregated query, four-card recurrence, and unique adjoint are born. The
query covector and cardinality offsets are the only device arrays bridging the
seam. Final release requires zero default-pool used/total bytes, zero pinned
free blocks, stable device total, device-free recovery within 16,777,216 bytes,
process-private recovery within 268,435,456 bytes, and host-available recovery
within 536,870,912 bytes. These three allowances are release/infrastructure
quantities and cannot decide admission, numerical error, latency, or quality.

payload.

## Terminal classes and kill criteria

The first terminal is exactly one of `completed_pass`,
`live_admission_rejected`, `allocation_rejected`, `scientific_rejected`, or
`infrastructure_failure`. Every class is permanent. A numerical, allocator,
release, runtime, protocol, source, wall, or artifact failure kills the owner;
it does not authorize a tolerance change or retry. Kill also if source seal
finds the result present, target execution reachable from tests, a second
output path, post-outcome configuration, nonexclusive creation, missing
`fsync`, omitted raw telemetry, an unpriced temporary, forward/adjoint
overlap, an ambient parent-process pool allowance, lower-width substitution,
or a systems outcome selecting truncation.
