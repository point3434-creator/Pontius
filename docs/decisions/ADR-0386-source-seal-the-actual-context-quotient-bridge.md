## Ownership and warm authority

The bridge reports unit-typed, nonadditive ledgers. Consumer-resident NumPy
payload is 15,888,996 bytes. Separately retained host-validation NumPy payload
is 84,972 bytes, including the factorized-belief masks/factors and automaton
bond metadata. The host structure also retains exactly 45 local/physical card
entries and 990 physical hand records; those counts are not mislabeled as
bytes. Warm-mutable NumPy payload is 79,216 bytes and is a subset view of
resident unary and mode-factor buffers, so it must not be added to resident
bytes as another allocation.

`compile_warm_inputs` can replace only belief unary weights and terminal path
mode factors. It recomputes the frozen legal context, physical/local mapping,
factorized hand topology, retained base factors, topology digest, terminal
semantics, and bridge/automaton identity before rebinding. A changed query
mask or same-shaped changed terminal automaton rejects. A stale board,
reordered full hand axis, wrong shape, negative mode factor, or nonfinite
factor also rejects. Returned warm arrays are contiguous and read-only.

No preparation count is converted into wall time, and none of these byte
views includes Python-object heap, upstream belief ownership, CUDA context,
allocator cache, scratch, recurrence state, solver state, or a complete
consumer. The result therefore cannot answer whether one iteration, solve, or
action fits the 15-second contract.

## Pre-seal corrections

Four controls materially improved the source before this seal. First, the
initial reduced test applied the zero-chip settlement ceiling to an aggregate
Float64 expectation and rejected a `4.263256414560601e-14` rounding
difference. The authority was split correctly: exact settlement remains zero
per assignment, while aggregate contraction remains under the precommitted
`2e-11` numerical gate. No tolerance changed.

Second, `FullWidthOneSeatBelief` rejected a reordered full axis at its own
constructor, before the warm compiler. The control now records that upstream
fail-closed authority and separately exercises a valid stale-card belief at
the warm boundary; it does not forge an invalid semantic belief merely to hit
a later branch.

Third, the draft ownership ledger priced a Python card tuple as 45 times eight
numeric bytes while omitting the separately retained 79,224-byte factorized
belief. That semantic/numerical coincidence was removed. Only exact NumPy
`nbytes` contribute to byte totals; Python/card/hand structure is reported in
entries, and resident versus warm views are explicitly nonadditive.

Fourth, a frozen dataclass could be copied with changed topology or automaton
payload while retaining stale identity fields. Warm rebinding now
reconstructs the legal source contract and recomputes both identities before
accepting new factors. Adversarial changed-mask and changed-terminal controls
prove the rejection. The required paired and unpaired source-seat permutation
controls were also added before sealing.

These were source-review corrections inside an open implementation boundary,
not retries of a one-shot owner, post-outcome population changes, numerical
relaxations, or favorable result substitutions. The ADR-0385 config, context,
reduced axes, exact and Float64 ceilings, and claims boundary remain byte-
identical.
