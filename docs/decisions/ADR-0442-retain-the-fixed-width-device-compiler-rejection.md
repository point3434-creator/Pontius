## Structural successor

The defect is broader than an operator forgetting to run a developer shell.
The experiment bound the CUDA compiler and its flags but left NVCC's required
host compiler behind ambient `PATH`. Tool identity was therefore narrower than
the compile toolchain identity actually consumed.

A successor must have fresh protocol, campaign, header, launcher, runner,
reader, and result identities. Before source seal it must bind a supported x64
MSVC installation, exact `cl.exe` path and version, activation script identity,
and the resulting compiler/include/library environment. Its external-directory
handshake must begin with scrubbed ambient compiler paths, activate only the
bound toolchain, prove that `cl.exe` resolves to the bound file, and still make
zero compiler or device calls. The sole later owner invocation must rebind the
same identities before calling NVCC. Merely adding `cl.exe` to the operator's
shell, reusing this result path, or changing compiler flags after outcome is
forbidden.

Provisioning Visual Studio Build Tools is a machine-wide package installation
with material disk and license surface. Repository autonomy does not silently
authorize it. The repo can freeze the successor only after that external
prerequisite is explicitly authorized and present.
