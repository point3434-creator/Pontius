## Question

What did the sole ADR-0458 invocation establish, and may its absent result
identity be reused because the failure occurred before journal creation?

## Decision

Retain the exact invocation as an unjournaled pre-owner infrastructure
rejection and permanently consume the ADR-0458 command and v1 result identity.
The repository was exactly clean at commit
`88148da07324c13b79c72ea494b14167a975c001`, and the result was absent before
the command. The public launcher activated the frozen host environment,
replaced `os.environ`, entered `execute_owner_to_path`, and failed in the first
`strict_git_metadata()` call before `DurableEvidenceJournalWriter.create`.
The process returned one; the result remains absent.

The cause is a phase-specific executable identity error. ADR-0443 already
binds `C:\Program Files\Git\cmd\git.exe` by exact size and SHA-256, and that
absolute executable is present. The activated compiler mapping intentionally
does not resolve relative `git`. ADR-0458's runner nevertheless invoked the
string `git` after replacing the environment. An executable available in the
operator shell and an executable available in the scrubbed owner environment
are different semantic quantities. The source seal tested the former and the
public owner consumed the latter.

No retry is permitted. Absence of a journal does not restore experimental
authority: the command crossed its invocation boundary and returned an
outcome. A successor needs fresh protocol, campaign, module, dependency,
launcher, reader, controls, and result identities. Its only scientific input
may be the byte-identical ADR-0458 source; its only mechanism change may be
absolute, hash-bound Git dispatch, with a source control exercising the real
post-replacement environment rather than a synthetic pre-replacement shell.

This rejection contains no evidence about CUDA compilation, resource use,
arithmetic correctness, topology speed, target fit, or decision quality. It is
rejected-invocation tax at the source-identity plumbing seam. The missing
journal is itself a process finding: failures before the durable owner cannot
be called typed owner terminals, and future source controls must distinguish
the two lifecycles explicitly.

## Consequences

- ADR-0458 and its absent v1 result path are permanently closed.
- A fresh successor may reuse the frozen scientific bytes but not the consumed
  runner identity or command.
- Relative executable lookup after environment replacement is prohibited when
  an exact host-manifest executable already exists.
